SECTION 01

Problem Statement

Why today's credit card marketplace is broken — and why users leave before converting.

⚠️
The core issue: India's credit card market has 100M+ addressable users, yet card discovery journeys are static, generic, and trust-eroding — resulting in drop-off rates above 70% on most aggregator platforms.

Current State Problems

😩 Information Overload

Users face 50+ card options with dense feature tables. No prioritisation, no personalisation. They can't determine which card matches their actual lifestyle.

📋 Rigid Questionnaires

Traditional forms ask 15–20 fields upfront (income, employer, PAN, DOB) before showing a single result. Users abandon before seeing value.

🔒 Trust Deficit

Users don't understand what data is being collected, why, and how it's used. Fear of hard credit pulls causes high exit rates at the data-consent stage.

🎯 Poor Matching Quality

Most aggregators show the same "popular" cards regardless of user profile. A fuel-heavy driver and a frequent flier get identical recommendations.

📉 High Drop-off Rates

Industry average completion rate for card application flows is under 30%. Friction at every step compounds to a terrible funnel.

💸 Missed Revenue

For FreechargeBiz, each unmatched user is a lost referral fee. Poor recommendations also lead to lower card activation and spend — hurting LTV.

Opportunity

Freecharge sits on a rich dataset: UPI transaction history, prepaid recharges, bill payments, and existing user financial profiles. Combined with SMS-based spend intelligence and soft bureau pulls, FreechargeBiz can deliver a sub-5-question, AI-driven recommendation that feels personalised from the first interaction — while being transparent and trust-building throughout.

SECTION 03

Core Features

Grouped by module, ordered by user interaction sequence.

Module A — Smart Onboarding & Consent

  • Progressive disclosure: Show value before asking for data. Hero screen shows a curated card gallery before any form.
  • Modular consent: Users pick which data sources to share (SMS, bureau soft-pull, UPI statement upload). Each option clearly explains the benefit and privacy guarantee.
  • Mobile-first OTP verification: Phone number capture triggers a soft identity match against the Freecharge user base — pre-filling known data silently.
  • Trust signals: "No hard credit pull", "Data encrypted", "Withdraw anytime" shown persistently during consent.

Module B — Contextual Data Collection

  • Conversational micro-survey: Maximum 4 questions, chip-based multi-select and sliders — no text input required.
  • SMS analysis (with consent): Parse bank SMSes to auto-detect: top spend categories, average monthly spend, active lenders, card EMI obligations.
  • Bureau soft pull: Retrieve CIBIL / Experian score range (not exact score) to filter eligible cards. Displayed back as "Good / Excellent / Outstanding" — no number shown to avoid anxiety.
  • Freecharge transaction graph: Internal signal — recharge frequency, bill payment categories, UPI transaction volume used as behavioural proxies.

Module C — AI Recommendation Engine

  • Multi-factor scoring: Each card scored against (a) spend category match, (b) income-based eligibility, (c) user preference, (d) bureau eligibility band, (e) existing card portfolio gap.
  • Explainability layer: Every recommendation comes with 3 human-readable "Why this card fits you" reasons — driven by the actual data signals, not static copy.
  • Ranked alternatives: Show top match + 3 alternatives. User can tap any alternative to see a full comparison and swap it to primary.
  • Benefit calculator: "You could earn ₹X in cashback per year based on your ₹Y monthly spend" — a real-time projection shown on the result page.

Module D — Application & Handoff

  • Instant apply flow: Pre-filled application form using data already collected. User only provides PAN, DOB, and employment details they haven't shared.
  • In-app status tracking: Application status card in Freecharge home screen (Submitted → Under Review → Approved → Card Dispatched).
  • Smart nudges: Push/SMS notification at each status update. If rejected, automatically surface the next-best eligible card.
  • Re-engagement: 30-day re-recommendation trigger — if a user didn't apply, re-run the engine with updated bureau data and surface a fresh recommendation.

SECTION 05

Technical Architecture

A layered, API-first architecture designed for low-latency recommendations and graceful degradation.

🏗️
Design principle: Every layer must be independently operable. If the bureau API is slow, the recommendation engine runs on self-declared data. If SMS parsing fails, declared spend categories take precedence. Graceful degradation over hard failures.
🖥️ PRESENTATION LAYER (Client)
React Native (mobile) React.js (web) Progressive Web App Framer Motion (animations) WebSocket (real-time status)
🔌 API GATEWAY & ORCHESTRATION
Node.js BFF (Backend for Frontend) GraphQL API JWT Auth + OTP (2FA) Rate limiting Request caching (Redis) Axios circuit breaker
🤖 RECOMMENDATION ENGINE (Core)
Python (FastAPI) Scoring model (rule-based v1 → ML v2) Feature extraction pipeline Card eligibility filter Explainability module A/B test harness
📡 EXTERNAL INTEGRATIONS
Axis Bank Card API CIBIL / Experian Soft Pull API SMS Consent SDK (Perfios / FinBox) Account Aggregator (AA) Framework Setu / Bureau API Firebase Push Notifications
🗄️ DATA LAYER
PostgreSQL (user profiles) MongoDB (event logs) Redis (session cache) S3 (statement uploads) Kafka (event streaming) Snowflake (analytics DW)
🛡️ SECURITY & COMPLIANCE
AES-256 encryption at rest TLS 1.3 in transit RBI DPSP compliance DPDPA 2023 consent framework PCI-DSS (card data isolation) SOC 2 Type II

Recommendation Model — v1 vs v2

v1 — Rule-Based Scoring (MVP)

Each card has a weight vector across spend categories and preference dimensions. User's profile is dot-multiplied against card weights. Income eligibility acts as a hard filter. Fast, interpretable, and explainable — ships in week 4.

  • Latency: <50ms
  • Explainability: 100%
  • Accuracy: Baseline

v2 — ML Model (Post-MVP)

Gradient-boosted classifier trained on historical application + activation data. Features: spend patterns, bureau band, card tenure, peer cohort similarity. SHAP values drive the explainability layer.

  • Latency: <200ms
  • Training data: 90-day post-launch
  • Target: +15% conversion vs. v1

Data Flywheel

🔄
Every application outcome (approved / rejected / activated / high-spend) feeds back into model training. Over time, the engine learns which user signals most reliably predict card activation and 90-day spend — improving recommendation quality with each cohort.
SECTION 07

User Stories & Acceptance Criteria

Written in standard format. Grouped by epic.

Epic 1 — Onboarding & Consent

US-01 · Consent Screen
Must Have
"As a first-time user, I want to understand what data will be used and choose what I'm comfortable sharing, so that I can trust the platform before providing any personal information."
ACCEPTANCE CRITERIA
User sees three distinct data-sharing options with plain-English descriptions before any data is collected.
Each option can be toggled independently; selecting none still allows the user to proceed via self-declared data only.
A persistent privacy note states "no hard credit pull" and links to the full privacy policy.
OTP verification completes within 30 seconds; failed OTP shows a re-send option after 60 seconds.
Consent selections are logged with a timestamp and stored per RBI DPSP guidelines.
US-02 · Returning User Pre-fill
Should Have
"As a returning Freecharge user, I want my existing profile data (name, income, spend history) to be pre-filled in the recommendation form, so that I don't have to re-enter information I've already provided."
ACCEPTANCE CRITERIA
Returning users who log in via phone OTP see pre-populated spend category suggestions derived from UPI transaction history.
Pre-filled values are clearly labelled as "Based on your Freecharge activity".
User can override any pre-filled value before proceeding.
If no prior data exists, standard empty form is shown without error.

Epic 2 — Data Collection

US-03 · Spend Category Selection
Must Have
"As a user who spends heavily on fuel and dining, I want to quickly select my top spending categories from a visual grid, so that the engine understands my lifestyle without me having to type anything."
ACCEPTANCE CRITERIA
Category grid shows at least 6 options (Fuel, Travel, Dining, Shopping, EMI/Bills, Entertainment) with icons.
User can select up to 3 categories; a visual indicator shows selection count.
Attempting to select a 4th category shows an inline message "You can pick up to 3".
The Next button remains disabled until at least 1 category is selected.
Selected categories are stored in session and passed to the scoring engine.
US-04 · Monthly Spend Slider
Must Have
"As a user, I want to indicate my monthly card spend with a slider rather than typing an exact number, so that the process feels fast and frictionless."
ACCEPTANCE CRITERIA
Slider range is ₹5,000 to ₹2,00,000 with steps of ₹5,000.
Current value is shown in real-time in a large, prominent format (e.g., "₹30,000 / month").
Slider defaults to ₹30,000 (platform median).
Slider is keyboard-accessible and WCAG 2.1 AA compliant.
US-05 · SMS Spend Analysis
Should Have
"As a user who has given SMS consent, I want the engine to automatically detect my actual spending patterns, so that I get a more accurate recommendation without having to manually input anything."
ACCEPTANCE CRITERIA
If SMS consent is given, the system reads and parses bank SMSes via a certified SDK (e.g., FinBox, Perfios).
Parsing completes within 5 seconds; results are used to pre-select spend categories and populate the spend slider.
If parsing takes >5 seconds, the user proceeds with self-declared data; SMS results are merged when available.
Raw SMS content is never stored; only derived signals (category labels, spend ranges) are persisted.
User can review and dismiss any auto-detected category before proceeding.

Epic 3 — Recommendation Engine

US-06 · Primary Recommendation Display
Must Have
"As a user who has completed the survey, I want to see a single best-fit card with a clear match score and personalised reasons, so that I immediately understand why this card is right for me."
ACCEPTANCE CRITERIA
Result screen shows exactly one primary recommendation above the fold.
Match score is displayed as a percentage with an animated progress bar that fills on load.
At least 3 personalised "Why this card" reasons are shown, each derived from the user's actual inputs (not static copy).
Key benefit chips (cashback %, annual fee, lounge visits, etc.) are displayed as scannable data points.
An "Apply Now" CTA is visible without scrolling on a standard mobile viewport (375px wide).
US-07 · Alternative Card Browsing
Should Have
"As a user who wants to compare options, I want to see alternative card recommendations and swap any one to the top position, so that I feel in control of my decision."
ACCEPTANCE CRITERIA
At least 2 alternative cards are shown below the primary recommendation with their match scores.
Tapping an alternative card promotes it to primary and recalculates the "Why this card" section for that card.
A "Compare" button opens a side-by-side comparison modal (v2 scope; in v1 shows a toast "Coming soon").
US-08 · Benefit Calculator
Could Have
"As a user considering the Axis ACE card, I want to see a projected annual savings figure based on my stated spend, so that I have a concrete financial reason to apply."
ACCEPTANCE CRITERIA
Projected annual cashback / miles value is calculated using the user's stated monthly spend × card earn rate.
Annual fee is deducted to show net benefit ("₹4,800 cashback – ₹499 fee = ₹4,301 net gain").
Disclaimer: "Indicative estimate. Actual value depends on transaction categories and bank terms."

Epic 4 — Application & Post-Apply

US-09 · Instant Application Submission
Must Have
"As a user who has decided on a card, I want to apply in under 2 minutes with a pre-filled form, so that I don't lose momentum after the recommendation."
ACCEPTANCE CRITERIA
Application form is pre-filled with name, mobile, and income from earlier data collection.
User only needs to enter PAN and DOB to complete the form.
Form submits to Axis Bank API within 3 seconds of tapping "Submit".
Success screen shows a unique reference number and sets user expectation (24–48h TAT).
Submission event is tracked in analytics for funnel reporting.
US-10 · Rejection Recovery
Should Have
"As a user whose application was rejected, I want to immediately see the next best card I'm eligible for, so that I don't leave the platform without an option."
ACCEPTANCE CRITERIA
If Axis Bank API returns a rejection, the system immediately re-runs the scoring engine excluding the rejected card and adjusting the eligibility filter.
Rejection screen shows a sympathetic message + the next-best card with a new apply CTA.
Rejection reason (if provided by bank API) is translated into user-friendly language (e.g., "Your income range is below the requirement for this card").
All rejection events are logged for model improvement.

SECTION 11

Risks & Mitigations

🔴
Bureau API Latency / Downtime
CIBIL / Experian APIs can be slow (3–8s) or return errors during peak hours, breaking the user flow.
✓ Mitigation: Circuit breaker pattern. If bureau API times out in >3s, silently skip and run engine on self-declared data. Bureau data merged asynchronously when available.
🔴
SMS Consent Drop-off
Users may distrust SMS access even with clear consent language, limiting signal quality.
✓ Mitigation: SMS consent is optional. Value framing ("Get a more accurate match") is shown. A/B test consent copy. Engine works without it.
🟠
Axis Bank API Contract Delays
Bank API documentation and sandbox access can take 4–6 weeks to procure.
✓ Mitigation: Mock the Axis API in staging from week 1. Parallelize API negotiation with frontend development. Apply flow can use a Typeform fallback for the pitch demo.
🟠
Low Recommendation Accuracy (v1)
Rule-based scoring may surface a suboptimal card for edge-case user profiles, eroding trust.
✓ Mitigation: Curate weights carefully with data from Axis Bank's top-performing card cohorts. Add a post-recommendation "Was this helpful?" micro-survey to flag bad matches fast.
🟡
DPDPA 2023 Compliance
India's Digital Personal Data Protection Act 2023 mandates explicit consent, purpose limitation, and data deletion rights.
✓ Mitigation: All consent is explicit, logged, and timestamped. Data deletion endpoint built from week 1. Legal review of consent copy before launch.
🟡
Competition from Bank Direct Channels
Axis Bank may divert traffic to its own app, reducing referral value of FreechargeBiz.
✓ Mitigation: Differentiate on multi-card comparison, neutral advisory positioning, and Freecharge's existing user trust. Lock in an exclusive referral fee structure in the partnership agreement.
